locate

A searchable interface for archived coding sessions across all AI agent harnesses

🔍 Cross-Harness Search

Search across all archived sessions from Claude, Codex, Opencode, Cline, Pi, T3, GitHub Copilot, Cursor, and more.

🖤 Copilot-Style UI

Black background, white text. Left column session list, right column content. Selectable and copyable text.

⚡ Parallel Search

Configurable batch scanning (5/10/20) to prevent lag on large archives.

📂 No Copies

Reads session files directly from harness directories — no files are copied or moved.

🔧 MCP Server

Control locate from Claude, Cline, Opencode, GitHub Copilot, and other MCP-compatible clients.

🎯 /locate Skill

Agent skill that teaches models to use locate for session search without wasting tokens.

Installation

1. Download the App

Clone or download the repository:

git clone https://github.com/xen38/locate.git
cd locate
npm install

2. Run the App

npx electron .

3. Add Harness Directories

Open the menu (top-right button) → Harnesses → Add Folder, or click "Scan & Autodetect" to automatically find harness directories on your system.

MCP Server

The locate MCP server exposes session search as MCP tools, allowing AI assistants to search archived sessions without reading the interface or wasting tokens.

Install on GitHub Copilot

Add the following to your GitHub Copilot MCP configuration:

{
  "mcpServers": {
    "locate": {
      "command": "node",
      "args": ["/path/to/locate/mcp-server.js"],
      "env": {}
    }
  }
}

Available MCP Tools

  • locate_search — Search across all archived sessions by title and content
  • locate_read_session — Read the full content of a specific session
  • locate_list_sessions — List all sessions across configured harnesses
  • locate_list_harnesses — List configured harness directories
  • locate_add_harness — Add a new harness directory to scan

/locate Agent Skill

The /locate skill teaches agents to use the locate app for session search. When prompted with /locate <query>, the agent uses the locate app's search bar to find relevant sessions and returns the content to the workstation.

Key principle: The model never reads the interface directly — it uses the search bar and lets the search engine do the work, preventing token waste.

See skill/locate.md in the repository for the full skill documentation.
